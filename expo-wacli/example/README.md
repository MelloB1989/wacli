# expo-wacli example

A working demo app for [`expo-wacli`](../): links a WhatsApp account from the phone, lists chats,
opens a conversation, sends messages, and updates live as messages arrive — with the whole daemon
running inside the app.

## What it shows

- **Pairing-code login** (and QR as an alternative) — `src/screens/LoginScreen.tsx`
- **Connection status and the DND gate** — `src/screens/ChatsScreen.tsx`, `src/useWacliStatus.ts`
- **Chat list with pull-to-sync** — `src/screens/ChatsScreen.tsx`
- **Conversation view and sending** — `src/screens/ChatScreen.tsx`
- **Live events** driving the UI — every screen subscribes to `onEvent`
- **Errors surfaced honestly** — a send refused because DND is off or the chat is locked shows
  wacli's own message rather than a generic failure
- **Tap-to-copy pairing code** via `expo-clipboard` — you are about to retype eight characters into
  WhatsApp on this same phone, with no second screen to read them off

The app deliberately uses no navigation library. A four-case screen union in `App.tsx` keeps the
interesting part of the code about wacli rather than about routing.

## Run it

Built against **Expo SDK 57** (React Native 0.86, React 19). This is native code, so it needs a
**dev client** — it cannot run in Expo Go.

```bash
# 1. Build the native bindings (from the repo root)
./expo-wacli/scripts/build-bindings.sh android   # needs ANDROID_NDK_HOME
./expo-wacli/scripts/build-bindings.sh ios       # needs macOS + Xcode

# 2. Install. The module is the workspace root, so install there — one bun install covers
#    both packages and hoists a single shared react/react-native for them.
cd expo-wacli
bun install

# 3. Generate the native projects and run on a device
cd example
bunx expo prebuild --clean
bunx expo run:android
bunx expo run:ios
```

Use a **real device**. An emulator works, but linking a WhatsApp account to one burns a linked-device
slot the same as a phone does, and you only get about four.

## First run

1. Enter your number in international format and tap **Get pairing code**.
2. In WhatsApp on your phone: Settings → Linked Devices → Link a device → *Link with phone number
   instead*, and type the eight characters.
3. The app syncs and drops you on the chat list.
4. **Turn on "Allow sending"** before trying to send. wacli ships with that gate closed, so the
   first send fails by design until you arm it.

## Notes

`metro.config.js` watches the workspace root and resolves from both `node_modules` directories. bun
installs into a content-addressed store under `../node_modules/.bun` and symlinks names into place,
which Metro follows natively on this React Native version. There is deliberately no `blockList`
hiding the root's `react`/`react-native`: under a hoisted workspace those are the *only* copy,
shared by the module and the app, which is what keeps a single React instance.

The `android/` and `ios/` directories are generated by `expo prebuild` and gitignored. Regenerate
them rather than editing them; the config plugin in `../app.plugin.js` owns the native config.

On iOS the connection only lives while the app is foregrounded — see the
[module README](../README.md#what-works-where) for why. Messages that arrive while the app is away
appear after the next sync, which the chat list triggers on reconnect.
